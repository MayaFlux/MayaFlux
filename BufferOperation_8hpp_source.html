37 /**
38 * @enum ExecutionStrategy
39 * @brief Defines how operations in a pipeline are coordinated and executed
40 */
41 enum class ExecutionStrategy : uint8_t {
42 /**
43 * PHASED: Traditional phased execution (default)
44 * - All CAPTURE operations complete first (capture phase)
45 * - Then all processing operations execute (process phase)
46 * - Best for: accumulation, windowed analysis, batch processing
47 * - Predictable data availability, clear phase boundaries
48 */
49 PHASED,
50
51 /**
52 * STREAMING: Immediate flow-through execution
53 * - Each capture iteration flows immediately through dependent operations
54 * - Minimal latency, data processed as it arrives
55 * - Best for: real-time effects, low-latency processing, modify_buffer chains
56 * - Natural for operations that modify state continuously
57 */
58 STREAMING,
59
60 /**
61 * PARALLEL: Concurrent capture with synchronization
62 * - Multiple capture operations can run concurrently
63 * - Explicit synchronization points coordinate data flow
64 * - Best for: multi-source capture, independent data streams
65 */
66 PARALLEL,
67
68 /**
69 * REACTIVE: Data-driven reactive execution
70 * - Operations execute when input data becomes available
71 * - Dynamic dependency resolution
72 * - Best for: event-driven workflows, complex dependencies
73 * - Non-deterministic execution order
74 */
75 REACTIVE
76 };

80 /**
81 * @class BufferOperation
82 * @brief Fundamental unit of operation in buffer processing pipelines.
83 *
84 * BufferOperation encapsulates discrete processing steps that can be composed
85 * into complex data flow pipelines. Each operation represents a specific action
86 * such as capturing data, transforming it, routing to destinations, or applying
87 * conditional logic. Operations are designed to be chainable and support
88 * sophisticated scheduling and priority management.
89 *
90 * **Operation Types:**
91 * - **CAPTURE**: Extract data from a buffer using configurable capture strategies
92 * - **TRANSFORM**: Apply functional transformations to data variants
93 * - **ROUTE**: Direct data to audio or graphics buffers and streams
94 * - **LOAD**: Read data from containers into buffers with position control
95 * - **SYNC**: Coordinate timing and synchronization across pipeline stages
96 * - **CONDITION**: Apply conditional logic and branching to data flow
97 * - **DISPATCH**: Send data to external handlers and callback systems
98 * - **FUSE**: Combine multiple data sources using custom fusion functions
99 *
100 * **Example Usage:**
101 * ```cpp
102 * // Capture audio with windowed analysis
103 * auto capture_op = BufferOperation::capture_from(input_buffer)
104 * .with_window(512, 0.5f)
105 * .on_data_ready([](const auto& data, uint32_t cycle) {
106 * analyze_spectrum(data);
107 * });
108 *
109 * // Transform and route to output
110 * auto pipeline = BufferPipeline()
111 * >> capture_op
112 * >> BufferOperation::transform([](const auto& data, uint32_t cycle) {
113 * return apply_reverb(data);
114 * }, Buffers::ProcessingToken::AUDIO_BACKEND)
115 * >> BufferOperation::route_to_container(output_stream);
116 * ```
117 * @class BufferCapture
118 * ...existing intro...
119 *
120 * **Cycle Behavior:**
121 * The `for_cycles(N)` configuration controls how many times the capture operation
122 * executes within a single pipeline cycle. When a capture has `.for_cycles(20)`,
123 * the operation will capture 20 times sequentially, with each capture receiving
124 * incrementing cycle numbers (0, 1, 2... 19) and calling `on_data_ready()` for
125 * each iteration.
126 *
127 * This is distinct from pipeline-level cycle control:
128 * - `.for_cycles(20)` on capture → operation executes 20 times per pipeline cycle
129 * - `execute_scheduled(5, ...)` → pipeline runs 5 times total
130 * - Combined: 5 × 20 = 100 total capture executions
131 *
132 * **Example:**
133 * ```cpp
134 * auto pipeline = BufferPipeline::create(*scheduler);
135 * pipeline >> BufferOperation::capture_from(buffer)
136 * .for_cycles(10) // Capture 10 times per pipeline invocation
137 * .on_data_ready([](const auto& data, uint32_t cycle) {
138 * std::cout << "Capture #" << cycle << '\n'; // Prints 0-9
139 * });
140 * pipeline->execute_scheduled(3, 512); // Runs pipeline 3 times → 30 total captures
141 * ```
142 *
143 *
144 * @see BufferPipeline For pipeline construction and execution
145 * @see BufferCapture For flexible data capture strategies
146 */
