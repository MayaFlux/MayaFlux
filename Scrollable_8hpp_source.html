26/**
27 * @struct Scrollable
28 * @brief A clipped, scroll-offset viewport over content taller than it.
29 *
30 * Before place() is called, the struct carries only configuration. After
31 * place(), viewport_id, scroll, offset, buf, and cursor_out are populated.
32 * This mirrors the Element/Collapsible pattern: configure with setters,
33 * register with a single explicit call.
34 *
35 * Scrollable owns a background/hit-test element sized to the viewport and
36 * a LayoutCursor (cursor_out) scoped to that viewport, already bound to the
37 * live scroll offset via LayoutCursor::bind_scroll, so content placed
38 * through it lands at the correct on-screen position immediately, scrolled
39 * or not. It does not own or know what kind of content is placed inside
40 * it: track() registers an element id plus the caller's own reposition
41 * callback, invoked with that element's scrolled bounds on every scroll.
42 * This is the same shape as Collapsible::attach(): Scrollable moves bounds
43 * and asks the caller's callback to keep visuals in sync, it does not
44 * reach into arbitrary geometry functions to do that itself. indicator()
45 * follows the same principle for a scroll readout: Scrollable computes the
46 * two numbers (position, extent) and drives sync() on the caller's own
47 * element, but draws nothing itself.
48 *
49 * Wheel input over the viewport is wired by place() as the default
50 * trigger, but scroll_by() is a plain method: any other input source (a
51 * dragged indicator, a key, MIDI, anything) can drive scrolling by calling
52 * it directly, with no dependency on Context::on_scroll at all.
53 *
54 * @code
55 * auto panel = Scrollable {}
56 * .background_color({ 0.08F, 0.08F, 0.1F })
57 * .place(buf, surface, viewport);
58 *
59 * const Kinesis::AABB2D bounds = panel.cursor_out.advance(row_h);
60 * auto row_buf = Portal::Forma::create_buffer(
61 * window, Kinesis::filled_rect(bounds, color),
62 * Portal::Graphics::PrimitiveTopology::TRIANGLE_STRIP);
63 * const uint32_t id = surface.layer().add(
64 * Element {}.with_bounds(bounds).with_buffer(row_buf).non_interactive());
65 *
66 * panel.track(surface.layer(), id, bounds,
67 * [row_buf, color](Kinesis::AABB2D shifted) {
68 * row_buf->submit(Kinesis::filled_rect(shifted, color));
69 * },
70 * row_buf);
71 * @endcode
72 */

149 /**
150 * @brief Register an element for scroll reflow.
151 *
152 * Expands scroll->content_bounds to include base_bounds, so the clamp
153 * in scroll_by() always reflects everything tracked so far - no manual
154 * content-height bookkeeping needed. On every scroll, this element's
155 * bounds_hint is updated to base_bounds.translated(offset) and
156 * reposition is called with that same shifted region: reposition owns
157 * whatever resubmission its own content needs (a raw buffer resubmit,
158 * rebuilding a Mapped<T>'s geometry, anything). Scrollable does not
159 * inspect or constrain what kind of content id is.
160 *
161 * base_bounds is normalized against the current offset before it is
162 * stored, so it is always safe to pass cursor_out.advance()'s return
163 * directly - that return is already shifted by whatever offset is
164 * live right now (that is the whole point of LayoutCursor::bind_scroll:
165 * an element placed after scrolling already happened lands in the right
166 * spot immediately). Without this normalization an element tracked
167 * while scrolled would have that offset baked into its anchor and
168 * drift further out of place on every scroll after.
169 *
170 * @param layer Layer both the viewport and @p id were registered
171 * on. relate()s id under viewport_id so a cascading
172 * Layer::remove(viewport_id) tears this element down
173 * too - no separate tracked-ids bookkeeping needed.
174 * @param id Element id, already registered on the same Layer
175 * place() used.
176 * @param base_bounds This element's current on-screen NDC bounds - the
177 * direct return of cursor_out.advance(), scrolled or not.
178 * @param reposition Called with the scrolled bounds on every scroll.
179 * @param clip_buf Optional. When given, Kinesis::Scissor::from(viewport_bounds)
180 * is set on its render processor immediately, so the
181 * element is clipped to the viewport from the start.
182 * @return *this, so place()/track()/indicator() can chain into one
183 * expression for the common case of a single tracked item -
184 * see Portal::Forma::TextField::scrollable() for exactly that.
185 */
186 MAYAFLUX_API Scrollable& track(
187 Layer& layer,
188 uint32_t id,
189 Kinesis::AABB2D base_bounds,
190 std::function<void(Kinesis::AABB2D)> reposition,
191 const std::shared_ptr<Buffers::FormaBuffer>& clip_buf = nullptr);

207 /**
208 * @brief A self-contained wheel-scroll handler bound to this
209 * Scrollable's own state.
210 *
211 * place() wires exactly this behind the viewport's own on_scroll, but
212 * Context::handle_scroll dispatches to only the topmost element under
213 * the cursor (Layer::hit_test), so content drawn on top of the
214 * viewport - anything track()ed, since it registers after and so hit-
215 * tests first - never reaches the viewport's own on_scroll while the
216 * cursor sits over it. A caller in that position (TextField::
217 * scrollable() is exactly this case) registers the returned function
218 * on its own element's on_scroll instead of duplicating the wheel-
219 * delta-to-content-delta conversion by hand.
220 *
221 * Captures only this Scrollable's own shared state (scroll, offset,
222 * the tracked list, the indicator), the same shared_ptrs place()'s own
223 * wiring captures - safe to keep registered after this Scrollable
224 * value itself is destroyed, same as every other Context callback this
225 * struct wires.
226 *
227 * @param surface Surface owning the same Layer/Context place() used.
228 * @return A Context::ScrollFn-shaped callable, ready for on_scroll.
229 */
230 [[nodiscard]] MAYAFLUX_API std::function<void(uint32_t, glm::vec2, double, double)>
231 wheel_handler(Surface& surface) const;

233 /**
234 * @brief Attach a caller-built element as a live, draggable scroll
235 * indicator.
236 *
237 * Scrollable draws nothing itself. Build whatever Mapped<glm::vec2>
238 * your own geometry function produces - a bar, a squiggle, a sampled
239 * texture, anything computable from (position_frac, extent_frac) - via
240 * Portal::Forma::create<glm::vec2>, register it, and hand it here.
241 * position_frac is 0 at the top of content_bounds and 1 at the fully
242 * scrolled bottom; extent_frac is the viewport/content height ratio
243 * (how much of the content is visible at once), so a geometry function
244 * can size its own drawing without asking Scrollable anything further.
245 *
246 * On every scroll - wheel (place()'s default wiring), scroll_by(), or
247 * dragging this same element - the live fraction pair is written to
248 * el.state and el.sync() is called, the same "call sync() straight
249 * from the handler that changed the value, no polling" idiom
250 * Collapsible's own on_press already uses. track() also refreshes
251 * extent_frac (without a Layer, so el's hit region only, not
252 * bounds_hint, can lag very slightly until the next scroll -
253 * self-corrects on the first interaction after).
254 *
255 * Also wires on_drag on el.element.id: dragging maps the cursor's NDC
256 * y absolutely onto content offset within @p track, the same
257 * inverse-mapping idiom Geometry::vertical_fader uses for its own
258 * handle, routed through scroll_by() so drag and wheel scrolling stay
259 * in sync through one path. No handle-size compensation is applied,
260 * unlike vertical_fader - an indicator has no fixed rendered size for
261 * Scrollable to know about.
262 *
263 * @param surface Surface owning the same Layer/Context place() used.
264 * @param el Caller's Mapped<glm::vec2>, already registered on
265 * surface's Layer.
266 * @param track NDC region the drag is measured against; its full
267 * height maps to the full scrollable range.
268 * @return *this, for chaining - see track()'s @return.
269 */
270 MAYAFLUX_API Scrollable& indicator(Surface& surface, Mapped<glm::vec2> el, Kinesis::AABB2D track);
271
272private:
273 std::shared_ptr<std::vector<Tracked>> m_tracked;
274 std::shared_ptr<Mapped<glm::vec2>> m_indicator;
275};
