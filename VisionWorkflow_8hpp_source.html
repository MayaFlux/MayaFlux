32/**
33 * @struct LiveConfig
34 * @brief How a live workflow run is paced and which frames it delivers.
35 *
36 * With @c interval_seconds above zero the run takes a frame every interval on
37 * the graphics clock; at zero the work sets the pace.
38 *
39 * With @c apply_to set, the source is still what gets analyzed, but each
40 * analysis is applied to @c apply_to's frame of the same moment: crops,
41 * samples, annotation and tone come from that buffer instead of the analyzed
42 * frame. The buffer is read live, frame by frame, not once; when the work
43 * sets the pace its frame is copied in the tick the analyzed frame is taken.
44 */
45struct LiveConfig {
46 double interval_seconds {};
47 std::shared_ptr<Buffers::TextureBuffer> apply_to;
48};

106/**
107 * @class VisionWorkflow
108 * @brief Runs vision queries over video streams, image lists and texture
109 * containers, delivering what an extraction takes from each frame.
110 *
111 * The live methods set a run going on the engine: an analysis producer on the
112 * scheduler and a delivering consumer on the event manager. They need a
113 * constructed workflow, and accept any video stream: a camera, a video file
114 * or a dynamic stream. A run keeps going until its stream reaches its end,
115 * stop_all(), the workflow's destruction, or engine shutdown. The managers
116 * are held weakly, so a workflow kept past shutdown keeps nothing alive and
117 * stops nothing.
118 *
119 * The finite methods are static: they run to completion on the calling
120 * thread and need no engine, so call them where no other vision work is
121 * running.
122 *
123 * In every method an intent set in the query without its parameters runs
124 * with the defaults, and tracking and motion carry from one frame to the
125 * next. The extraction mode must produce an image.
126 */

147 * The stream is hooked to a buffer unless it already has one. Without a

206 /**
207 * @brief Run @p config's matrix on its source live and return a Chimera
208 * builder over a new layer array, for any image the run produces.
209 *
210 * Paced and sourced as process_to_buffer(). The layers, their sources and
211 * the rendering are declared on the returned builder, and the array itself,
212 * for a shader's mode, is its get_buffer(). Each analysis is
213 * handed to the matrix's extract(), so its analysis(), frame() and
214 * extraction() follow the run; the images of every sequence are read from
215 * its results() or, by intent, result(). Then each record entry appends
216 * its picked image, all together once per analysis, at the run's pace:
217 * one per interval, or as often as the work completes, which the matrix
218 * reports as analysis_rate(). The run stops as the other live runs do,
219 * and also once the Chimera that was started from the builder is stopped
220 * or dropped, or the builder is dropped unstarted. The Chimera outlives
221 * the run and keeps its last images.
222 *

224 * are gone, the matrix is null or the stream cannot be hooked.
