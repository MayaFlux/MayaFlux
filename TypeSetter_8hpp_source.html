41/**
42 * @brief Lay out a UTF-8 string into a sequence of screen-space quads.
43 *
44 * Every codepoint this text needs is rasterized (cached, if not already)
45 * before any quad is emitted, so a GlyphAtlas growth triggered partway
46 * through this text cannot invalidate the UV coordinates already baked into
47 * quads emitted earlier in the same call. This guarantee is per-call only:
48 * a LayoutResult held across later, unrelated lay_out() calls on the same
49 * atlas is not protected if the atlas grows afterward from something else.
50 *
51 * Every codepoint for which is_control() is true is never rasterized or
52 * counted as printable content. Among those, \t advances pen_x to the next
53 * tab stop and \n advances pen_y by atlas.line_height() and resets pen_x;
54 * every other control codepoint (including \r) is skipped with no side
55 * effect. This is the same is_control() identification raw-string text
56 * handling uses; only the reaction to it differs here.
57 *
58 * Consecutive non-control glyphs are kerned via FT_Get_Kerning() when the
59 * producing face (GlyphMetrics::face) has a kerning table. The previous
60 * glyph index resets to none across any control codepoint, across a
61 * wrap-induced line break, and whenever the producing face changes between
62 * consecutive glyphs: a glyph index is only meaningful within the face
63 * that assigned it, so a codepoint resolved through GlyphAtlas's fallback
64 * chain never gets kerned against a glyph from a different face.
65 *
66 * Wrapping at wrap_w is a pure render-bounds guarantee, not word-aware line
67 * breaking: it breaks mid-word freely, with no whitespace lookback. This is
68 * deliberate - correctness here means no glyph ever renders past wrap_w, not
69 * that words stay intact. Each glyph is checked before it is placed, against
70 * its own advance width times a 1.5x margin, so the decision to wrap accounts
71 * for the glyph about to be drawn rather than reacting one glyph late to
72 * cumulative pen_x history - the margin absorbs the gap between a glyph's
73 * advance and its true rendered width so a glyph is never placed half past
74 * the boundary. A tab is checked the same way against its own tab-stop
75 * advance (no margin, since it draws nothing itself) immediately after
76 * computing its destination, not deferred to the next glyph's turn.
77 *
78 * Bidirectional reordering and shaping are not performed. HarfBuzz slots in
79 * before the glyph index step when needed; the quad assembly loop and
80 * GlyphAtlas remain unchanged.
81 *
82 * Each quad's byte_offset is the position of its codepoint's first byte in
83 * @p text, letting a caller correlate a quad back to source text (styling,
84 * hit-testing, extraction) without re-decoding UTF-8 itself.
85 *
86 * @param text UTF-8 encoded input string.
87 * @param atlas GlyphAtlas to query and populate. May be modified (dirty
88 * flag set) if new glyphs are rasterized.
89 * @param pen_x Starting horizontal pen position in pixels.
90 * @param pen_y Starting vertical pen position in pixels (baseline).
91 * @param wrap_w Column to wrap at in pixels, or 0 to disable wrapping.
92 * @param tab_width Tab stop width in space-glyph-widths.
93 * @return LayoutResult containing quads and final pen position.
94 */
95[[nodiscard]] MAYAFLUX_API LayoutResult lay_out(
96 std::string_view text,
97 GlyphAtlas& atlas,
98 float pen_x = 0.F,
99 float pen_y = 0.F,
100 uint32_t wrap_w = 0,
101 uint32_t tab_width = 4);

203/**
204 * @brief Byte offset of the codepoint boundary nearest a screen-space point.
205 *
206 * Scans layout.quads for the line whose quads sit closest to @p y, then
207 * within that line for the ink quad @p x falls into (resolving to its left
208 * or right half), or, failing that, for the two quads bracketing @p x.
209 * lay_out() never emits a quad for a space, tab, or newline, so a point
210 * landing in the gap between two quads - or before the first / after the
211 * last quad on a line - has no ink to test against directly: that gap is
212 * resolved exactly by walking its few codepoint boundaries through x_at()
213 * (same pen_x/pen_y/wrap_w/tab_width as the original lay_out() call) and
214 * keeping whichever pen position lands closest to @p x, rather than
215 * guessing from ink edges that were never meant to mark it.
216 *
217 * A line with no quads at all (blank, or entirely whitespace) has nothing
218 * for the first scan to anchor on and is still not distinguishable from an
219 * adjacent line by this function - a real, if narrower, residual gap.
220 * Empty layout.quads (the whole text is blank or all-whitespace) returns 0.
221 *
222 * @param text Source UTF-8 string layout was produced from.
223 * @param layout LayoutResult to hit-test against.
224 * @param atlas GlyphAtlas layout was produced with.
225 * @param x Screen-space x coordinate, same space as layout's quads.
226 * @param y Screen-space y coordinate, same space as layout's quads.
227 * @param pen_x Pen origin x, matching the original lay_out() call.
228 * @param pen_y Pen origin y, matching the original lay_out() call.
229 * @param wrap_w Wrap column, matching the original lay_out() call.
230 * @param tab_width Tab stop width, matching the original lay_out() call.
231 * @return Byte offset of the nearest codepoint boundary.
232 */
