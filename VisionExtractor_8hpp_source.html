9/**
10 * @file VisionExtractor.hpp
11 * @brief GPU getter for what VisionAnalyzer found. Every method takes a
12 * Kinesis::Vision::VisionAnalysis and derives its geometry from
13 * whichever field is populated; an analysis with nothing in it
14 * extracts nothing. All pixel work runs on the GPU, the host only
15 * packs the analysis into buffers and dispatches.
16 *
17 * FunctionalOperation<shared_ptr<SignalSourceContainer>, vector<DataVariant>>,
18 * like VisionAnalyzer. run_operation reads the analysis from Datum metadata
19 * key "vision_analysis" (the key VisionAnalyzer::run_operation writes) and
20 * runs the method selected by VisionExtractMode, so a VisionAnalyzer ->
21 * VisionExtractor chain needs no adapter. mask() alone stays outside that
22 * path: it needs the VisionGpuExecutor that owns the label buffer.
23 */

51/**

53 * @brief Per-element measure select_element() ranks find_elements by, taken

66/**
67 * @brief How the extractor chooses among several found elements: rank by
68 * criterion, highest first when largest, lowest first otherwise.
69 * Proximity ignores largest and picks the element whose centre is
70 * closest to point.
71 */
72struct ElementFocus {

78/**
79 * @class VisionExtractor
80 * @brief Extraction from each VisionAnalysis field.
81 *
82 * find_elements: crop() one element, crops() all, mask() by label buffer,
83 * silhouettes() by contour polygon (no executor), sample_regions(), and
84 * select_element() to rank by shape. tracks and keypoints: patches() and
85 * sample_points(). measure_appearance: equalize() and expose(). detect_edges:
86 * edges(). estimate_motion: motion_mask(). Any field: annotate() draws
87 * everything found onto the frame.
88 *
89 * Which find_elements entry the single-element methods use comes from
90 * set_element_focus() when set (GPU-ranked by shape), otherwise from
91 * set_element_index() into contours (sorted by area when max_contours was
92 * set) or, with no contours, into boxes.
93 *
94 * Thresholds and sizes used by run_operation are set through setters, the
95 * same convention as the other operations; the direct methods take only
96 * the data and the dimensions of what they read or write.
97 *
98 * Image-producing methods share one output slot, so a returned image stays
99 * valid only until the next call that produces an image of the same size.
100 * Hold on to a result by using it (display, copy) before extracting again.
101 */
