17/**
18 * @struct TextField
19 * @brief An editable text region: keyboard/text-input wiring over an
20 * Element the caller already has a buffer for.
21 *
22 * Before place() is called, the struct carries no state. After place(),
23 * element_id, state, params, and field_bounds are populated. This mirrors
24 * the Scrollable/Collapsible pattern: place() takes a pre-built buffer
25 * (Portal::Forma::create_buffer at the call site) and does not itself
26 * depend on Forma.hpp - no file under Portal/Forma/ may, except Forma.cpp
27 * itself. Portal::Forma::create_text_field (in Forma.hpp) is the one-call
28 * convenience that builds the buffer and delegates here, the same split
29 * Portal::Forma::create<T> already has between itself and a Form<T>.
30 *
31 * Editing state lives in a Portal::Text::EditableText, mutated through
32 * Portal::Text::move()/erase()/insert_codepoint()/insert_literal() - this
33 * struct only wires Context callbacks to those operations and re-renders.
34 * It does not manage focus visuals; wire on_focus_gained/on_focus_lost
35 * separately, same as any other Forma element.
36 *
37 * Cursor movement beyond Left/Right/character-count needed no new
38 * Portal::Text API: Up/Down resolve via x_at() (current pen position) and
39 * index_at() (nearest byte at that x, one line_height() away) - the exact
40 * idiom test_text_input() (test_8.hpp) already used to verify x_at()/
41 * index_at() round-trip. A mouse click does the same, with the click's NDC
42 * position mapped into pixel space first (the inverse of the mapping
43 * caret_ndc() itself uses).
44 *
45 * A caret rides in the same buf as the text quad rather than owning a
46 * buffer, Element, or Layer entry of its own: it is a second
47 * Kakshya::MeshVertex quad (Kinesis::textured_mesh_rect at weight 0, a
48 * flat fill - forma_multi.frag already branches per-vertex on weight, so
49 * weight<=0 draws that vertex's own color with no texture read at all)
50 * appended after the text quad's 6 vertices in the same buf->submit()
51 * call. Every keystroke and every reposition() therefore resubmits both
52 * quads together (12 MeshVertex, 720 bytes) rather than only the one that
53 * actually moved - FormaBuffer::submit() has no partial-range write, so
54 * this is the whole buffer either way, and at this size it costs nothing
55 * to send it whole. Caret pixel position comes from Portal::Text::x_at()
56 * plus GlyphAtlas::ascender()/line_height(), matching the same pen_x=0,
57 * pen_y=ascender(), wrap_w=render_bounds.x origin press()/repress()
58 * already rasterize text at internally - Portal::Text needed no new API
59 * for this.
60 *
61 * params is a shared, mutable Portal::Text::PressParams: every keystroke's
62 * re-render reads *params fresh, so a caller can change it once (e.g. a
63 * focus-driven background color) and have every subsequent keystroke see
64 * it, without re-wiring anything.
65 *
66 * buf is exposed (same convention Scrollable/Collapsible use) so a field
67 * can be clipped or scrolled with no TextField-specific plumbing: pass it
68 * directly as Scrollable::track()'s clip_buf to get scissor-to-viewport
69 * clipping for free, and wire reposition() as the track() reposition
70 * callback to move the field on scroll:
71 *
72 * @code
73 * auto buf = Portal::Forma::create_buffer(
74 * window, Graphics::PrimitiveTopology::TRIANGLE_LIST,
75 * std::vector{ std::pair{ std::string("text"), std::shared_ptr<Core::VKImage>{} } });
76 *
77 * auto params = std::make_shared<Portal::Text::PressParams>(
78 * Portal::Text::PressParams { .color = { 0.9F, 0.9F, 0.9F, 1.F }, .render_bounds = { 800, 64 } });
79 *
80 * auto field = TextField {}.place(buf, surface, bounds, params, "hello");
81 *
82 * // Living inside a Scrollable, composed by hand:
83 * auto panel = Scrollable {}.place(viewport_buf, surface, viewport_bounds);
84 * panel.track(surface.layer(), field.element_id, field.bounds(),
85 * [field](Kinesis::AABB2D shifted) mutable { field.reposition(shifted); },
86 * field.buf);
87 * @endcode
88 *
89 * scrollable() is the fluent equivalent of that same composition, for the
90 * common single-field case - but the Scrollable itself is entirely the
91 * caller's: build and configure it however (place(), indicator(),
92 * background_color(), wheel_speed() - all fluent) before calling
93 * scrollable(), which only needs a buffer for itself, that already-placed
94 * Scrollable to track into, and how tall to grow relative to its viewport.
95 * Everything Scrollable already owns (the viewport buffer, its bounds, any
96 * indicator) stays there - this struct has no reason to know about it a
97 * second time. Portal::Forma::create_text_field(..., scrollable=true) in
98 * Forma.hpp is nothing more than a call to this.
99 */

151 /**
152 * @brief Fluent creator: place this field inside an already-placed
153 * Scrollable, growing itself taller than its viewport and
154 * track()ing itself in, wired to scroll past a fixed clip.
155 *
156 * scroller is entirely the caller's: build and configure it first -
157 * Scrollable::place(), and optionally indicator()/background_color()/
158 * wheel_speed(), all fluent - then pass it here by reference. This
159 * method reads scroller.bounds() for the viewport region, places this
160 * field at a content region content_multiplier times that viewport's
161 * height (top-aligned, same width), and calls scroller.track() with
162 * this field's own buf as clip_buf and reposition() as the reflow
163 * callback. The same three-call composition shown in the class doc,
164 * done once here so callers building the common single-field case do
165 * not have to repeat it - nothing about the viewport, its buffer, or
166 * any indicator passes through this call, because Scrollable already
167 * owns all of that.
168 *
169 * Also wires scroller.wheel_handler() onto this field's own element:
170 * the field sits on top of the viewport and is added to the Layer
171 * after it, so it hit-tests first, and Context::handle_scroll only
172 * ever dispatches to the topmost element under the cursor - without
173 * this, the wheel would do nothing while the cursor sits directly over
174 * the field's own text instead of the viewport's empty margin.
175 *
176 * Also relate()s element_id under scroller.viewport_id, so
177 * Portal::Forma::destroy(surface, element_id) tears down the
178 * scroller's viewport too, even though scroller itself is never owned
179 * or stored here - only its Layer-side element needs freeing this way.
180 *
181 * @param in_buf Pre-created buffer for the field's text quad.
182 * @param surface Surface to register the field's element on -
183 * must be the same Surface scroller was placed on.
184 * @param scroller Already-placed Scrollable to grow and track into.
185 * @param in_params Shared render params. A default-constructed
186 * one is allocated if null.
187 * @param initial_text Starting text. Cursor starts at its end.
188 * @param content_multiplier Content height as a multiple of scroller's
189 * viewport height. Default 3x: enough headroom
190 * to type past the viewport before hitting the
191 * limit, not so much that most content sits
192 * unreachable below a near-empty field.
193 * @return *this, with results populated.
194 */

201 float content_multiplier = 3.F);
